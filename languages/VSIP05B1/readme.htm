This document contains late-breaking or other information about the Visual Studio .NET Industry Partner Program (VSIP) 2005 Beta One release.  This Readme is intended to help you work around known issues in this release of VSIP 2005 Beta One.

  1. You must run Visual Studio 2005 Exp with the default General Development Settings.  If you don't, your commands may not show up in the menus.

    2. If you're launching Visual Studio 2005 Exp for the first time, you'll be asked to choose your default environment setting.

    • Select General Development Settings, then click Start Visual Studio.

    If instead you’ve already launched Visual Studio 2005 Exp.

    • From the Tools menu, select Import/Export Settings...
    • Click the Reset IDE Settings radio button.
    • Select General Development Settings from the list, then click Reset Settings.
    • When prompted, Don't Save your current settings.
       
  2. When using VSIP help do not use the VSIP filter. At this time, using that filter will cause some VSIP content to be hidden.
     
  3. In the automation Immediate Toolwindow sample, the Script control project is not set to be registered for COM interop.  Trying to create the control gives a Class not registered error.  To work around this problem, add a Guid attribute to the ScriptControl class, and check the Register for COM Interop property.
     
  4. Keybindings that package developers write will not show up in the Visual Studio UI. This is due to the fact that users are forced to select a profile, which gives them only the keybindings explicitly defined in the profile. Since VSIP developers can't participate in the preinstalled profiles including the general profile, they can't hook their keybindings in.
     
  5. The DynamicMenu sample does not compile. When you attempt to build, mt.exe throws an error about the build output. To correct this problem, go to the Project Properties for the C++ project, then select Linker -> Manifest File.  Change "Generate Manifest" to No.
     
  6. VSIP 2003 Extras and VSIP 2005 Beta One use the same PackageWizard progid and classid.  If both are installed (side-by-side), and then one is uninstalled, the wizard will no longer function.  There is no workaround at this time.
     
  7. VSIP 2003 Extras and VSIP 2005 Beta One both use the ENVSDK_REGKEY environment variable.  If both are installed (side-by-side), and then one is uninstalled, C++ packages created in VSIP 2003 Extras will register in the 7.1 hive rather than in the experimental 7.1Exp hive.  There is no workaround at this time.
     
  8. VSIP 2003 Extras and VSIP 2005 Beta One both register wizards in the same location.  Whichever one is installed last will break the wizards of the other.
     
  9. Running devenv /setup from the command line will cause the following empty folders to be generated:

Visual Basic
Visual C#
Visual J#
Web Projects

These folders can be deleted or ignored.

  1. The Setup.msi sample does not install the right binaries and so does not register them either. It installs only the project item and project templates.  There is no workaround for this issue.
     
  2. When you create a MyCPrj project and add an item you will get a debug assertion. This is related to changes to the ALT CComBSTR class. This happens when you need to pass a BSTR* for an [out] param. This particular assertion is coming from CFileVwProjNode::OnCmdAddItem method. To workaround the issue, create an array of BSTRs (see below) and pass that to the IVsAddProjectItemDlg::AddProjectItemDlg method.

    BSTR rgbstrFilters[] = {bstrFilter};
     
  3. The VSIP 2005 regpkg.exe program does not register VSIP 2003 Extra packages correctly in the Visual Studio 2005 Beta One IDE, even though the output from the tool suggests it succeeded. Use  the VSIP 2003 Extras VsipRegPkg.exe program instead.
     
  4. You will see an unhandled exception when you try to reopen a wizard too quickly or return to the welcome screen from later pages in a wizard.  If you see this exception, click Continue to return to Visual Studio.  The only data lost is the data given to the wizard.
     
  5. The VSIP 2005 wizards create packages for Visual Studio 2005, even though their description says they target Visual Studio 2003.

     
  6. Due to a late breaking change in Whidbey Beta1, a New Help project cannot be compiled. The workaround would be to build the project from the command line using hxcomp.exe.
